# Captain Bond Static Website — Enhanced Version

This version does not need Node.js or npm.

## How to run
1. Unzip the folder.
2. Open `index.html` by double-clicking it.
3. For a more realistic test, open PowerShell in this folder and run:
   ```powershell
   python -m http.server 8000
   ```
   Then open: `http://localhost:8000`

## Deploy to Vercel

This is a static site with no install or build step. The included `vercel.json` serves the project root. No package.json, framework migration, server process, or environment variables are required.

1. Push the project, including the new programme files and images, to your Git repository.
2. In Vercel, add a project and import that repository.
3. Select the root folder containing `index.html` as the Root Directory. Framework Preset: **Other**.
4. The checked-in configuration sets Build Command and Install Command to empty strings and Output Directory to **.** (the project root). Remove any old dashboard overrides that conflict with these settings.
5. Deploy, then open the deployment URL and check navigation, images, programme details, and telephone links.

Alternatively, with Node.js installed, run `npx vercel` from this folder for a preview deployment, then `npx vercel --prod` when ready to publish to production. Sign in and select your intended account/project when prompted. The generated `.vercel/` folder is ignored by Git.

`.vercelignore` allows only the website assets and configuration into deployments; tests, documentation, and the Google Apps Script source stay in the repository. The Apps Script runs separately on Google, not on Vercel.

Browser storage is tied to the website origin. Existing votes, ideas, and agent selections on a different domain remain there and will not automatically appear on the new Vercel domain. This hosting change does not delete them.

Reference: [Vercel configuration](https://vercel.com/docs/project-configuration/vercel-json) and [deployment file exclusions](https://vercel.com/docs/deployments/vercel-ignore).

## Scheduled family programmes

Memories Meet Digital and Travelling without Borders are featured in the existing directory. `programmes.js` holds their separate scheduled data, explicit Singapore dates, session times, venues, capacity in family dyads, and official phone numbers. Original activities keep IDs 1?6 and their agent scores. The original theme names are now used by the filter controls, with digital, cultural, and family facets and a clear action.

The original programme posters are included in `images/Memories Meet Digital.png` and `images/Travelling Without Borders.png`. Both appear uncropped in the directory and programme details. Each details view has a View Full Poster link that opens the original PNG in a new tab for zooming and scanning the original registration QR code. Telephone registration remains available; no online registration service has been tested. The poster files are unchanged, including their logos and QR codes.

Families choose a session and 1?4 dyads, review the telephone summary, and call the official number. They provide their name and contact number directly to staff. No network submission, booking confirmation, duplicate reservation, or capacity promise is generated by this website. Telephone registration requires no backend configuration. Online registration would require an official URL or a separately verified service with validation, duplicate protection, and server-side capacity checks. `google-apps-script.js` and its existing spreadsheet columns remain unchanged.

Staff must verify the weekday discrepancy: **23 December 2026, 30 December 2026, and 6 January 2027 are Wednesdays**, despite the Memories Meet Digital poster's Thursday description. All advertised dates are retained exactly and displayed with their actual weekday. Dates remain visible after the session starts, with registration disabled. There is no weekly recurrence rule.

### Verification

Run data and Singapore date-boundary tests with:

```powershell
node --test tests/scheduled-programmes.test.cjs
node --check programmes.js
node --check script.js
```

Optional browser regression needs an installed Playwright or playwright-core module and Chromium. No dependency or build step has been added to the website. Start `python -m http.server 8000 --bind 127.0.0.1`, then run `node tests/browser.cjs`. If Playwright is outside this checkout, set `PLAYWRIGHT_MODULE` to its installed module path first.
